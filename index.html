Blog - CSS Sprites

Sprites are a pretty ingenious way to reduce the number of server requests that a webpage requires to display images. Instead of making an individual request for a file for each image shown, all of the images used on a webpage are combined into a single image, known as a spritesheet.[1][2][3] This spritesheet is fetched once, and each image on the web page is simply displaying a specific portion of the larger spritesheet. While technically speaking, multiple images combined into a single image means a larger filesize than the smaller images would cumulatively be, this is more efficient because each request made to the server requires handshaking, meaning that multiple requests means making those handshakes multiple times.[3] Another reason to use this is that browsers limit the number of concurrent requests, which can cause the display to look odd as the page loads images one after another instead of all at the same time.[3]

Making the Spritesheet

This can be the most annoying part of this technique, especially if you don't plan ahead what images you need or if the images change during development. You need to have a single image file containing all of the images you need for your webpage. There are automated tools that can make creating and updating the spritesheet easier, or you can create this image manually. Simply open your images in your favorite editor, place them on the same canvas, and export them as a single image. I used Gnu Image Manipulation Program (GIMP), but any similar program such as Adobe Photoshop or Microsoft Paint should work.

From there, we need to edit the HTML of our website. inside the <img> tags for your images it is important to add an id that you can refer to in the CSS stylesheet. One small bit of advice is that while you can't leave the src attribute blank, it doesn't matter what it is, because it'll be overwritten by the portion of the spritesheet we specify in the CSS stylesheet. So pointing the src to the smallest image you can might be a good idea.

Next, in the CSS stylesheet, for each <img> tag, create a section and specify the width and height of your image and whatever other styling you want. Specifically for the spritesheet, the important properties that you'll want to use are background-image and background-position.

The arguments you'll use for these properties are:
background-image: url(yourSpriteSheet.png);
where yourSpriteSheet.png is whatever you've named your spritesheet.
and
background-position: X Y
where X and Y are the value for how far you need to slide the background image to show the correct portion for the image

Some example code for the HTML I created to show this is below:

                    
<!DOCTYPE html>
<html>
<head>
    <link href="css/style.css" rel="stylesheet">
</head>
<body>

    <img id="smiley" src="img/blank_example.png" width="1" height="1"
    alt="an image of a smiley face">
    <img id="triangle" src="img/blank_example.png" width="1" height="1" 
    alt="an image of a triangle">
    <img id="circle" src="img/blank_example.png" width="1" height="1"
    alt="an image of a circle">
    <img id="X" src="img/blank_example.png" width="1" height="1"
    alt="an image of an X">
    

</body>
</html>

And the example code for CSS:

                    
#smiley{
  width: 240px;
  height: 240px;
  background-image: url(../img/spriteSheetExample.png);
  background-position: 0 0;
}

#triangle{
  width: 240px;
  height: 240px;
  background-image: url(../img/spriteSheetExample.png);
  background-position: 240px 0;
}

#circle{
  width: 240px;
  height: 240px;
  background-image: url(../img/spriteSheetExample.png);
  background-position: 0 -240px;
}

#X{
  width: 240px;
  height: 240px;
  background-image: url(../img/spriteSheetExample.png);
  background-position: 240px -240px;
}

This should give you an output like this:

While implementing css sprites takes some planning ahead and is much more involved than using the traditional <img> tags, I think that many web developers could benefit from using this technique. Not only can it save your servers from getting hammered by request after request per image, it can be essential in preventing large webpages with many images from looking wrong as the browser iterates through requests sequentially. Instead, the page loads slightly slower, but all elements appear at the same time.
